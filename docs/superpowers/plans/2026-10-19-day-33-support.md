# Day 33 Support Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; all implementation
> and PR publication are already authorized in this conversation.

**Goal:** A working RAG support service using MCP ticket/user context.
**Architecture:** stdio CRM → scoped context → product RAG → OpenRouter → HTTP/CLI.
**Tech Stack:** Python 3.10+ standard library; shared MCP, index and LLM modules.
**Spec:** days/day-33-support/SPEC.md

## Global Constraints
- Synthetic TaskFlow data only; no production CRM or authentication claims.
- Loopback HTTP; standard library only; no browser operation.
- OPENROUTER_API_KEY for cloud; explicit extractive --demo without a model.
- Ticket ownership checked before context reaches retrieval or LLM.
- Independent branch day33-support from origin/main; PR is the delivery.

## Review Focus
- Foreign/missing ticket must fail before any document or LLM invocation.
- A second request must never retain the first user's context.
- Unknown questions must not invent product features or successful actions.
- Invalid HTTP sizes/JSON/origin and a busy generator must get bounded errors.
- Real MCP process must close on success and failure; no stdout protocol noise.
