# День 8 — Работа с токенами

## Задание

Добавить в код агента подсчёт токенов: для текущего запроса, для всей истории
диалога и для ответа модели. Сравнить короткий диалог, длинный и такой, который
превышает лимит модели. Показать, как растут токены и стоимость, и что ломается
при переполнении.

**Формат сдачи:** видео + код.

## Токены считаются в двух разных местах, и это не одно и то же

| | откуда берётся | точность | зачем |
|---|---|---|---|
| **После** запроса | `usage` в ответе API | точно | узнать, сколько уже потрачено |
| **До** запроса | свой счётчик | оценка | узнать цену, пока ещё можно передумать |

Второе — вся суть дня. После отправки считать нечего: API сам вернул числа,
они в `Stats` с дня 6. А вот «сколько будет стоить следующий запрос» нужно
уметь ответить **заранее** — влезет ли диалог в окно, не пора ли подрезать
историю, во что обойдётся реплика.

Настоящий токенизатор DeepSeek живёт в пакете `transformers`, а в этом репозитории
нет ни одной внешней зависимости. Поэтому [shared/tokens.py](../../shared/tokens.py) —
честная посимвольная оценка с коэффициентами, **измеренными по живому API**,
и с измеренной же погрешностью.

## Что показывает агент перед каждым запросом

```
  Следующий запрос весит ~190 токенов
    обвязка запроса        30  служебная разметка
    роль                   58  уезжает в КАЖДОМ запросе
    история диалога       102  оплачивается заново
    сам вопрос              0
```

Удивляет здесь не размер вопроса. Вопрос — это десяток токенов. Платите вы
за роль и за историю, которые уезжают заново каждый раз.

## Сколько стоит символ

Наивное «четыре символа на токен» — неверно, и промахивается не на проценты.
Измерено на `deepseek-v4-flash`:

| тип текста | символов на токен |
|---|---:|
| английский | 6.03 |
| код | 3.59 |
| русский | 3.21 |
| цифры | 1.31 |

**Английский текст почти вдвое дешевле русского** при той же длине, а цифры —
втрое дороже. Плюс у любого запроса есть постоянная обвязка в **30 токенов**:
на слове «привет» она составляет 84% счёта.

Роль агента из дня 6 весит **63 токена** и оплачивается в каждом запросе.

### Насколько врёт оценка

```bash
python3 demo.py calibrate
```

| | промах |
|---|---:|
| одиночные тексты, в среднем | 5.8% |
| диалог (роль + 3 пары + вопрос) | +7.8% |

Оценка стабильно завышает — это сознательно: лучше подготовиться к большему
счёту, чем неожиданно упереться в лимит.

Надбавка за разметку сообщения (`MESSAGE_OVERHEAD`) тоже измерена, а не взята
с потолка. Первая версия ставила там 4 наугад, и оценка диалога промахивалась
на **+21.6%**. Чистый замер — один и тот же текст одним сообщением против
двух — дал **+2 токена на сообщение**, и промах упал до 7.8%.

## Как растёт счёт

```bash
python3 demo.py growth
```

Восемь реплик подряд, живые числа:

| № | вход | из них история | нарастающим |
|---:|---:|---:|---:|
| 1 | 54 | — | 54 |
| 2 | 64 | +10 | 118 |
| 4 | 82 | +9 | 273 |
| 6 | 109 | +13 | 478 |
| 8 | 130 | +13 | 725 |

**Вес одного запроса растёт линейно** — примерно на 11 токенов за реплику.
**А сумма, за которую платят, растёт квадратично:**

```
  ушло на вход всего            725 токенов
  если бы без истории           432 токенов
  переплата за перечитывание    293 токенов
```

На восьми репликах это копейки. На сотне десятая реплика оплачивает девять
предыдущих, сотая — девяносто девять. Лечится окном памяти из дней 6–7:
агент держит последние N пар, и вес запроса перестаёт расти. Плата за это —
агент забывает начало разговора.

Проверяется прямо в чате:

```bash
python3 cli.py --memory 3      # узкое окно: счёт перестаёт расти
python3 cli.py --no-window     # окно снято: растёт квадратично
```

## Что ломается при переполнении

```bash
python3 demo.py overflow
```

У `deepseek-v4-flash` окно — **1 048 576** токенов, туда живым диалогом
не упереться ни за какие деньги. Поэтому берём модели поменьше через OpenRouter.
И выясняется, что переполнение ломается **двумя разными способами**.

### Явно — и это удача

`meta-llama/llama-3.2-1b-instruct`, окно 60 000:

```
HTTP 400: This endpoint's maximum context length is 60000 tokens.
However, you requested about 130312 tokens (130307 of text input, 5 in the output).
```

Видно сразу, текст внятный, можно обработать.

### Молча — и это настоящая проблема

`google/gemma-2-27b-it`, окно 8 192:

| отправили | API насчитал |
|---:|---:|
| 7 758 символов | 1 313 токенов |
| 38 802 символов | **1 122** токенов |
| 103 476 символов | **1 122** токенов |

Сто тысяч символов и восемь тысяч — насчитано одно и то же, 1 122.
Вход обрезали. При этом:

- **ошибки нет**, HTTP 200;
- `finish_reason` = `stop`, как при нормальном ответе;
- ответ приходит осмысленный.

Агент потерял начало диалога и **не знает об этом**. Никто ему не сказал.
Именно поэтому вес запроса надо считать самому, до отправки, — иначе про
потерю узнаёшь только по тому, что агент вдруг «забыл» сказанное в начале.

## Из чего состоит день

| Файл | Что делает |

| [../../shared/tokens.py](../../shared/tokens.py) | оценка токенов, цены, лимиты окон |

Новое в агенте:

```python
agent.weigh("вопрос")     # из чего сложится следующий запрос
agent.spent               # сколько денег утекло за диалог
agent.stats.average_prompt  # средний вес запроса — растёт по мере диалога
```

