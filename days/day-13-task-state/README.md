# День 13 — Состояние задачи (Task State Machine)

## Задание

Реализовать состояние задачи как конечный автомат: этап, текущий шаг,
ожидаемое действие. Проверить паузу на любом этапе и продолжение без
повторных объяснений.

## Автомат, а не ярлык

Разница между «полем с этапом» и конечным автоматом — в рёбрах. Этап нельзя
поставить какой вздумается, можно только перейти по существующему ребру:

```
planning ──→ execution ──→ validation ──→ done
    ↑            │              │
    └────────────┘              │
                 ↑──────────────┘
```

| откуда | куда можно |
|---|---|
| планирование | выполнение |
| выполнение | проверка, **планирование** (план не годится) |
| проверка | готово, **выполнение** (не прошло) |
| готово | никуда |

Два ребра назад — не украшение. Без них автомат описывал бы только счастливый
путь, которого в работе не бывает.

Попытка прыгнуть через этап получает не молчаливое присваивание, а отказ
с объяснением:

```
Из «планирование» нельзя сразу в «готово». Доступно: «выполнение»
```

## Модель предлагает — автомат решает

После каждой реплики модель докладывает, где задача. Но **права менять этап
у неё нет**: она возвращает предложение, а допустим ли переход — проверяет
код по `TRANSITIONS`.

Проверено: на реплику «давай сразу закроем» модель предложила `done`,
автомат отклонил, этап остался `planning`. При этом текущий шаг обновился —
шаг это свободный текст, его ограничивать незачем.

Отклонения показываются в интерфейсе намеренно: это единственное наглядное
доказательство, что автомат работает, а не записывает всё подряд.

## Пауза и продолжение

Состояние лежит **отдельно от диалога** — в своей таблице, привязанной к чату.
Поэтому пауза не зависит ни от окна контекста, ни от того, жив ли процесс:

```
исходно            этап execution, шаг «пишем парсер выгрузки»
⌘Q                 процесса нет
запуск снова       этап execution, шаг «пишем парсер выгрузки»
```

Агент продолжает с того же места, потому что состояние записано явно,
а не выводится заново из переписки.

Состояние переносится при переименовании чата и наследуется веткой; при
удалении чата стирается вместе с ним — чат и есть задача.

## Приложение

```bash
cd days/day-13-task-state
python3 web.py                  # http://127.0.0.1:8000
./build_app.sh && open "dist/День 13.app"
python3 cli.py                  # то же в терминале
```

Вверху окна — полоса этапов: текущий подсвечен, пройденные помечены галочкой.
Рядом кнопки переходов, и **кнопки недопустимых переходов неактивны** —
из «планирования» кнопки «готово» просто нет, с подсказкой почему.

Справа — цель, текущий шаг, ожидаемое действие и журнал переходов.
Каждый чат слева — отдельная задача со своим состоянием.

Команды в CLI: `/состояние`, `/задача <цель>`, `/дальше <этап>`, `/шаг`, `/ждём`.
