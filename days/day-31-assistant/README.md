# День 31 — Ассистент разработчика

## Задание

Через RAG подключить ассистента к документации проекта (README, docs,
схемы). Через MCP — к самому проекту: минимум текущая git-ветка, по
желанию список файлов или diff. Реализовать `/help`, отвечающий
на вопросы о проекте.

## Что уже было и чего не хватало

RAG по документам готов с дня 21, git через MCP — с дня 17, чат
с историей — с дня 25. Нового здесь одно: **соединить два источника
в одном ассистенте и научить выбирать между ними.**

И ещё: у сервера дня 17 **нет текущей ветки**. Там только история —
статистика, поиск по коммитам, файл во времени. А это минимум задания.

## Документы объясняют, git показывает

Разделение не формальное, оно определило всю постройку.

| источник | на что отвечает | пример |
|---|---|---|
| документы через RAG | как устроено, почему так сделано, что показал замер | «почему сжатие бывает дороже» |
| git через MCP | что происходит прямо сейчас | «в какой я ветке» |

На вопрос о ветке в документации ответа нет и быть не может — она
меняется каждый день. На вопрос о замере сжатия нет ответа в git.
Ассистент, который на первый вопрос складно пересказывает README,
бесполезен, даже если текст выглядит гладко.

## Второй MCP-сервер: состояние, а не история

`server.py` даёт пять инструментов о том, что сейчас:

| инструмент | что отдаёт |
|---|---|
| `current_branch` | ветка, последний коммит, расхождение с origin |
| `working_state` | незакоммиченное: изменено, добавлено, удалено, новое |
| `diff` | текст изменений, во всём дереве или в одном файле |
| `list_files` | структура проекта, с фильтром по каталогу и образцу |
| `recent_commits` | последние коммиты с датами |

Сервер отдельный, а не дополнение к дню 17, и это по опыту дня 20:
девятнадцать инструментов без карты маршрутов дают промахи. Здесь их
одиннадцать, разведённых по смыслу — `state__*` про сейчас, `hist__*`
про историю.

Вместе: 583 куска документации и 11 инструментов git.

## /help

```bash
python3 assistant.py --check                 # всё ли на месте
python3 assistant.py /help "в какой я ветке"  # разовый вопрос
python3 assistant.py                          # диалог
```

В диалоге есть и прямые команды без модели — они быстрее и дешевле там,
где ответ однозначен:

```
/ветка        /состояние        /файлы shared        /очистить
```

## Проверка: откуда взят ответ

```bash
python3 check.py          # 9 вопросов трёх видов
python3 check.py --local  # на локальной модели
```

Девять вопросов, у каждого заранее известно, где лежит ответ:

| вид | сколько | что проверяется |
|---|---|---|
| `state` | 4 | вызван ли нужный инструмент git |
| `docs` | 3 | обошёлся ли **без** инструментов |
| `both` | 2 | сделано ли и то и другое |

Проверяется не складность ответа, а источник. Лишний вызов инструмента
на вопрос по документам — тоже промах: это секунды и токены впустую.

| модель | state | docs | both | всего | источник не тот |
|---|---|---|---|---|---|
| облако | 4/4 | 3/3 | 2/2 | **9/9** | 0 |
| `qwen2.5:3b` | 4/4 | 1/3 | 1/2 | 6/9 | 2 |

Локальная модель хорошо умеет **вызвать** инструмент (4/4 на вопросах
о состоянии), но хуже умеет **не вызывать**: на вопрос про `build_app.sh`
полезла в `diff`. И дважды не вытащила факт из выдержек. Это согласуется
с днями 26–29: структурированные решения даются ей тяжелее свободного
текста.

## Три находки по ходу

**Формулировка решает маршрут.** Вопрос «какая стратегия нарезки победила
в дне 21» уводит в `hist__day_summary`: слово «день» выглядит как запрос
к истории. Он же без «в дне 21» идёт в документы, как и должен. Это
не дефект модели, а цена разделения по смыслу — границу приходится
обозначать в самом вопросе.

**Git экранирует кириллицу.** В списке каталогов появлялась мусорная
строка `"days: 3`: git оборачивает пути с не-ASCII в кавычки. Лечится
флагом `core.quotepath=false` при каждом вызове.

**`AI_ADVENT_REPO_MIRROR` не экспортировался.** Переменная присваивалась
в `build_app.sh`, но в строку `export` не попала — потерялась ещё в дне 21,
когда я переписывал эту строку, и переехала во все последующие дни.
Там это не замечали, потому что git-инструментами не пользовались.
В собранном приложении история молчала, пока не нашлось.

**Рабочее дерево в `.app` недоступно, и это неустранимо.** Приложение
из Finder не видит `~/Documents` (macOS TCC), а зеркало репозитория
содержит только историю — файлов в `git clone --mirror` нет вовсе.
Поэтому:

| где запущено | документы | история | состояние файлов |
|---|---|---|---|
| терминал | ✓ | ✓ | ✓ |
| `.app` из Finder | ✓ | ✓ (из зеркала) | ✗ |

Сервер в этом случае не возвращает пустоту, похожую на «изменений нет»,
а говорит прямо: «НЕТ ДОСТУПА К РАБОЧЕМУ ДЕРЕВУ». Разница существенная:
пустой ответ ассистент пересказал бы как «у вас всё закоммичено».

Для полной работы запускайте из терминала. Приложение годится для
вопросов по документации и истории.

## Что видно в окне

Слева — состояние репозитория живьём, оно обновляется само. Под каждым
ответом видно источник: оранжевым инструменты git, сиреневым выдержки
из документов. Для вопросов из контрольного набора окно сразу говорит,
верный ли выбран источник.

## Запуск

```bash
cd days/day-31-assistant

python3 assistant.py --check
python3 assistant.py                 # диалог с /help и командами
python3 check.py                     # 9 вопросов
python3 server.py --selftest         # проверить инструменты состояния
python3 web.py                       # http://127.0.0.1:8000
./build_app.sh && open "dist/День 31.app"
```
