# День 19 — Пайплайн: инструменты в цепочке

## Задание

Составить цепочку из нескольких MCP-инструментов: найти → сжать → сохранить
в файл. Инструменты должны работать вместе, передавая результат друг другу.

## Что сделано

Три инструмента поверх репозитория, сцепленные в конвейер:

| Инструмент | Что делает | Вход | Выход |
|---|---|---|---|
| `search` | ищет по коммитам (`git log --grep`) и файлам (`git grep`) | строка запроса | артефакт с найденным |
| `summarize` | сжимает через модель | **номер артефакта** | артефакт с выжимкой |
| `save_to_file` | пишет на диск с заголовком | **номер артефакта** | артефакт с путём |

Плюс три служебных: `run_pipeline` (все три шага одним вызовом), `show_chain`
(родословная артефакта), `list_artifacts`.

## Главное решение: данные ходят по номеру, а не текстом

Наивный вариант — инструмент возвращает найденный текст, модель получает его
в контекст и передаёт следующему инструменту. Так делать нельзя по трём
причинам, и все три проверяемы:

**1. Дорого.** Замер на живом прогоне:

```
артефакт #9 (данные)      :  6307 знаков
вернулось в модель        :    91 знак
не прошло через контекст  :  6216 знаков (99%)
```

Инструмент возвращает не данные, а квитанцию: «сохранено в артефакт #9,
6307 знаков, sha 354b1e3ab1fc». Модель оперирует номером.

**2. Модель искажает.** Всё, что прошло через генерацию, переписано — пусть
на пару символов. Для «сжать» это и нужно, для «передать дальше» —
недопустимо.

**3. Не проверить.** Когда данные идут мимо модели, целостность видна
глазами. Каждый шаг показывает хэш своего выхода и хэш входа следующего:

```
1. search       готово #6 2344 знака sha 65880cfa32ce
2. summarize    готово #7 1103 знака sha 4e02c9f00a04 | вход #6 2344 знака sha 65880cfa32ce
3. save_to_file готово #8   67 знаков sha a411b9ea3005 | вход #7 1103 знака sha 4e02c9f00a04
```

Хэши сцеплены: выход шага равен входу следующего. Ничего не потерялось
и не переписалось по дороге.

## Артефакт

Единица обмена — запись в SQLite (`shared/artifacts.py`):

```python
@dataclass
class Artifact:
    id: int          # то, чем обмениваются инструменты
    kind: str        # search | summary | file
    title: str
    content: str     # сами данные — их модель не видит целиком
    tool: str        # кто породил
    source_id: int   # из какого артефакта вырос → отсюда строится цепочка
```

`source_id` даёт родословную: по любому артефакту можно размотать всю цепочку
назад до исходного поиска. Это и печатает `show_chain`.

## Два способа запустить одно и то же

**Кнопкой.** Наверху окна — запрос и имя файла. Три шага загораются по
очереди, под каждым видно номер артефакта, размер и хэш.

**Словами.** Агент сцепляет инструменты сам, подставляя номера:

```
вы › Найди всё про MCP, сожми и сохрани в мкп-из-чата.md

🔧 pipe__search(query="MCP", scope="all")
     │ Найдено и сохранено в артефакт #9
     │   коммитов: 4, файлов: 23
🔧 pipe__summarize(artifact_id=9, style="короткая выжимка про MCP")
     │ Выжимка готова, артефакт #10
     │   вход: #9, 6307 знаков (sha 354b1e3ab1fc)
🔧 pipe__save_to_file(artifact_id=10, filename="мкп-из-чата.md")
     │ Сохранено: …/memory/pipeline/мкп-из-чата.md

#9 → #10 (сжатие ×4.8) → #11 файл
```

Обратите внимание: во втором вызове стоит `artifact_id=9` — номер из первой
квитанции. Модель сцепила шаги, не увидев данных.

## Мелочи, которые всплыли в работе

**`def list()` внутри класса ломает аннотацию.** Метод с таким именем
перекрывает встроенный `list`, и `-> list[Artifact]` в соседнем методе
падает с `TypeError: 'function' object is not subscriptable`. Переименован
в `recent()`.

**Пустой чат нельзя переименовать.** `store.rename()` отказывает, пока в
сессии нет ни одной реплики, — переносить нечего. Поведение общее для всех
дней с 11-го, не особенность этого.

**`open` не перезапускает работающее приложение.** После пересборки сначала
⌘Q, иначе проверяете старую сборку.

## Запуск

```bash
cd days/day-19-pipeline

python3 web.py                      # http://127.0.0.1:8000
python3 server.py                   # голый MCP-сервер по stdio
./build_app.sh && open "dist/День 19.app"
```

Приложение из Finder не видит `~/Documents` (macOS TCC), поэтому работает
с зеркалом репозитория в `~/Library/Application Support/AI Advent/repo.git` —
`build_app.sh` обновляет его при каждой сборке.
