# День 4 — Температура

## Задание

Выполнить один и тот же запрос при `temperature` = 0, 0.7 и 1.2. Сравнить ответы по
точности, креативности и разнообразию. Сформулировать, для каких задач подходит каждая
настройка.

**Формат сдачи:** видео + код.

## Почему задач две, а не одна

В задании сказано «один и тот же запрос», но три названные грани на одном запросе
не измеряются: у задачи с правильным ответом нельзя померить креативность, а у творческой
нет правильного ответа, чтобы померить точность. Поэтому здесь два запроса, каждый
прогоняется при всех трёх температурах:

- **точность** — «что выведет этот код», ответ проверяемый
- **креативность** — «объясни рекурсию через метафору»
- **разнообразие** — меряется на обоих

## Как меряется каждая грань

**Точность.** Эталон не объявляется, а **добывается запуском кода**:

```python
def ground_truth() -> int:
    buffer = io.StringIO()
    with contextlib.redirect_stdout(buffer):
        exec(CODE, {})
    return int(buffer.getvalue().strip())
```

Задача выбрана так, чтобы в ней сталкивались два эффекта Python сразу: `x=i` захватывает
значение в момент объявления (0, 1, 2, 3), а само `i` в теле лямбды берётся при вызове,
когда оно уже равно 10. По отдельности модель знает оба, вместе они встречаются редко.
Правильный ответ — **60**.

**Разнообразие.** Среднее попарное различие ответов по мере Жаккара на множествах слов:
0 — тексты совпадают дословно, 1 — ни одного общего слова.

**Креативность.** Оценивает модель-судья, и оценивает **вслепую**: все пятнадцать метафор
идут ей одним списком, вперемешку и без подписи, при какой температуре получена каждая.
Судья работает при `temperature=0`, чтобы оценки не гуляли от запуска к запуску. Знай он
температуры — оценка поехала бы вслед за ожиданиями, а не за текстом.

## Результаты

Реальный прогон, `deepseek-chat`, 5 прогонов на температуру:

| t | Точность | Разных ответов | Разнообразие | Оригинальность | Понятность |
|---|:--------:|:--------------:|:------------:|:--------------:|:----------:|
| **0.0** | 5/5 | 4/5 | 0.49 | 5.4 | 9.0 |
| **0.7** | 5/5 | 5/5 | 0.73 | 6.0 | 9.0 |
| **1.2** | 4/5 | 5/5 | 0.84 | 6.6 | 8.8 |

### `temperature=0` — это не детерминизм

Главная находка дня. При нулевой температуре из пяти метафор **четыре оказались разными** —
дословно совпала только одна пара. Хотя «нулевая температура» в голове звучит как
«одинаковый ответ на одинаковый запрос».

Так и должно быть. `temperature=0` означает «всегда бери самый вероятный токен», но сами
вероятности считаются на GPU с плавающей точкой, запросы группируются в пачки разного
размера, и порядок суммирования плавает. Разница в последнем знаке — и на развилке, где
два токена почти равны, выбирается другой. Дальше расхождение накапливается.

Практический вывод: **нельзя закладываться на побайтовое совпадение ответов даже при
`temperature=0`**. Нужна воспроизводимость — кешируйте ответ сами, а не надейтесь на API.

### Точность падает только на 1.2

При 0 и 0.7 — по 5/5. При 1.2 один прогон дал **14 вместо 60**: модель выбрала менее
вероятное продолжение на развилке рассуждения и уехала не туда.

Заметьте, что 0.7 не хуже нуля по точности, но заметно разнообразнее (0.73 против 0.49).
Для задач, где важен верный ответ, но не нужна побайтовая повторяемость, 0.7 ничего
не стоит.

### Температура меняет формулировку, а не идею

Второй неочевидный результат. Посмотрите на метафоры: при **всех трёх** температурах
модель выдаёт одно и то же — два зеркала друг напротив друга. Меняются слова, обороты,
длина, но образ один.

Единственное исключение появилось на 1.2 — матрёшка. Одна штука из пятнадцати.

То есть температура крутит **разнообразие формулировок, а не пространство идей**. Если
нужен принципиально другой ход мысли, температуру повышать бесполезно — надо менять промпт:
запрещать очевидное («не используй зеркала»), задавать другую область («метафора из
кулинарии»), просить сразу несколько вариантов в одном ответе.

Оригинальность по оценке судьи растёт (5.4 → 6.0 → 6.6), но растёт скромно — как раз
потому, что вариации идут вокруг одного образа.

### Понятность держится

9.0 → 9.0 → 8.8. На 1.2 текст ещё не разваливается: у DeepSeek шкала до 2.0, и 1.2 —
это ещё не край. Полноценный бред начинается ближе к верхней границе.

## Для каких задач какая настройка

| Температура | Куда | Почему |
|-------------|------|--------|
| **0 – 0.3** | извлечение данных, классификация, парсинг, SQL и код, вызов функций | Нужен предсказуемый ответ. Разнообразие тут — чистый вред: сегодня распарсилось, завтра нет |
| **0.7** | диалог, объяснения, черновики текстов, суммаризация | Точность как у нуля, но формулировки живее. Разумная настройка по умолчанию для всего, что читает человек |
| **1.0 – 1.3** | мозговой штурм, генерация вариантов названий, слоганы | Когда нужно много непохожих заготовок и есть кому их отбирать. Ошибки не страшны — плохие варианты просто выбрасываются |
| **выше 1.3** | почти никогда | Связность начинает сыпаться, а идеи всё равно не становятся принципиально новее |

Отдельно: если нужно **много разных вариантов**, дешевле и надёжнее попросить их
в одном ответе списком, чем гонять пять запросов с высокой температурой. Один запрос
вместо пяти, и модель сама следит, чтобы варианты не повторялись.

## Что показать на видео

1. `ground_truth()` — эталон получается запуском кода, а не рассуждением о нём.
2. Сам код-задачу: два эффекта Python в одной строке.
3. Метафоры при `t=0` — показать, что они **не совпадают**, хотя температура нулевая.
4. Таблицу: точность падает только на 1.2, разнообразие растёт монотонно.
5. Главный вывод: температура меняет формулировку, а не идею — во всех пятнадцати
   ответах одни и те же зеркала.
