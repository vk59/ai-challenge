# День 12 — Персонализация ассистента

## Задание

Создать профиль пользователя, описать предпочтения (стиль, формат, ограничения),
подключить профиль к каждому запросу. Проверить ответы для разных профилей
и то, что ассистент учитывает автоматически.

## Результат

Один и тот же вопрос — «Как хранить пароли пользователей?» — через четыре
варианта. Модель, температура и роль одинаковые, истории нет. Меняется
**только профиль**, поэтому вся разница принадлежит ему:

| профиль | знаков | код | токенов |
|---|---:|:---:|---:|
| без профиля *(контрольный)* | 2547 | да | 1024 |
| senior | **1227** | да | 461 |
| аудитор | 1757 | **нет** | 603 |
| новичок | 2087 | да | 729 |

Профиль `senior` («сухо, как коллеге», «не объяснять базовые понятия») дал ответ
**вдвое короче** контрольного. Профиль `аудитор` с прямым запретом «НЕ приводить
примеры кода» — единственный, кто обошёлся без кода. Никаких указаний в самом
вопросе при этом не было.

Начала ответов:

```
без профиля  Коротко: пароли никогда не хранят в открытом виде и не шифруют…
senior       Только хеш медленным KDF, соль на пользователя, сравнение timing-safe…
аудитор      **Требования к хранению паролей пользователей** — Алгоритм (KDF)…
новичок      Коротко: пароль никогда не хранят в открытом виде. Хранят только…
```

## Профиль — это не память

Разделение принципиальное, и оно продолжает модель памяти дня 11:

| | что это | кто заполняет | где живёт |
|---|---|---|---|
| Долговременная память (`profile`-записи) | факты **о** человеке: «имя: Иван» | агент сам из диалога | `longterm` |
| **Профиль** (день 12) | указания **как** с ним говорить | человек сознательно | `profiles` |

Первое агент узнаёт, второе ему задают. Поэтому профилей может быть несколько
и они переключаются одним движением — иначе «сравнить ответы для разных
профилей» просто не проверить.

Поля профиля: `tone`, `format`, `level`, `language`, `constraints`.

## Как подключается

Профиль уезжает в системный промпт **сразу за ролью, перед всякой памятью** —
это указания о форме ответа, и они должны действовать независимо от того, что
агент успел запомнить:

```
[Как отвечать этому собеседнику]
- тон: сухо, как коллеге
- уровень: senior, 10 лет опыта
- ограничения: не объяснять базовые понятия
```

Стоит это денег, как и всё в промпте: в статусной строке приложения есть
отдельный счётчик «из них профиль». Профиль на 5 полей — это примерно
60–80 токенов **в каждом запросе**.

## Приложение

День сделан приложением, потому что персонализацию надо видеть рядом:

```bash
cd days/day-12-personalization
python3 web.py                 # http://127.0.0.1:8000
./build_app.sh && open "dist/День 12.app"
```

Слева — список чатов, справа — профиль и три слоя памяти из дня 11.
Главная кнопка — **«Сравнить профили»** (⌘D в приложении): берёт вопрос
из поля ввода и задаёт его всем профилям сразу, ответы встают колонками.

По одному ответу персонализацию проверить нельзя — непонятно, профиль
подействовал или модель просто так ответила. Колонки рядом снимают этот вопрос.

Сравнение идёт в отдельной служебной сессии и не пачкает текущий чат:
после прогона агент возвращается туда, где был, с тем же профилем.

Терминальные варианты, если нужно показать код:

```bash
python3 demo.py                # то же сравнение в консоли, с проверками
python3 cli.py --profile senior
```

В `cli.py` есть `/профиль <имя>`, `/создать`, `/кто` — последняя показывает,
что именно уезжает в модель.

## Честно про ограничения

**Профиль — просьба, а не гарантия.** Он часть промпта, и модель может его
проигнорировать. В `demo.py` поэтому проверяется не «нравится ли ответ», а
выполнено ли **прямое указание**: у аудитора — отсутствие кода, у новичка —
нумерованный список, у senior — длина. Это единственное, что можно проверить
объективно.

**Заготовки создаются при первом запуске** (новичок, senior, аудитор) — иначе
пользователь видит пустой список и не понимает, что писать в поля.
