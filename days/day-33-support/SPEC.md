# День 33 — поддержка пользователей

## Результат
Самостоятельный локальный мини-сервис с HTTP-чатом и CLI. Он отвечает на вопросы
о вымышленном TaskFlow по FAQ и документации через RAG, а контекст пользователя
и тикета получает по настоящему MCP stdio из синтетического JSON.

Одинаковый вопрос «Почему не работает авторизация?» должен давать разные ответы
для SSO_REQUIRED, ACCOUNT_LOCKED и EMAIL_UNVERIFIED. Каждый ответ показывает
идентификатор тикета, вызванный MCP-инструмент и использованные источники.

## Решение
- `crm_mcp.py`: read-only `get_support_context(user_id, ticket_id?)`. Проверяет
  принадлежность тикета до выдачи данных; неизвестные ID и чужой тикет — ошибка.
- `knowledge.py`: документы только из `docs/*.md`, структурная нарезка общего
  `shared/index.py`. Облако — существующий векторный Index и OpenRouter embeddings;
  демо — локальное извлечение по терминам и точным кодам ошибок, без API.
- `assistant.py`: сначала MCP, затем поиск с учётом вопроса и фактов тикета,
  затем LLM через `shared/llm.py`. Пользователи/тикеты не индексируются.
  Деморежим явно помечен и возвращает выдержку, не имитирует вызов модели.
- `service.py` + `chat.html`: loopback HTTP, GET /health, POST /api/ask,
  запуск CLI с `--question`. Ограничения тела/вопроса, безопасные ошибки,
  запрет внешних Origin и неизвестных Host. Контекст не переносится между запросами.
- Автономные тесты реального MCP, RAG, изоляции, HTTP и мок генерации;
  CI отдельно проверяет реальную модель и эмбеддинги при наличии секрета.

## Границы
Python 3.10+, стандартная библиотека, существующий shared-код, без новых пакетов.
Облачный режим использует OPENROUTER_API_KEY; без ключа он не подменяется демо.
Только вымышленные данные. Это локальная консоль оператора, не публичная CRM:
нет production-аутентификации/тенантов и не поддерживается внешний bind.
Нет изменений реальной CRM, закрытия тикетов, отправки писем или merge PR.
Ответы модели не являются выполненными действиями; документы/JSON — данные,
а не инструкции. При недостатке знаний — честный отказ и передача оператору.

## Готовность
Реальный MCP transport; проверенная принадлежность тикета; разные причины входа;
проверяемые ссылки на локальные документы; API+UI; зелёные тесты и облачный smoke;
отдельный PR от main; в конце короткий сценарий видео текстом в чате.
