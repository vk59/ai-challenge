# День 33 — ассистент поддержки

Мини-сервис отвечает по FAQ и документации, используя контекст пользователя и
тикета через **MCP stdio**. Продукт TaskFlow и все CRM-записи вымышлены.
Внешних Python-пакетов нет; требуется Python 3.10+.

## Запуск

Из корня репозитория:

```bash
# Без ключа: MCP + локальный поиск + выдержки, без вызова LLM
python3 days/day-33-support/service.py --demo

# AI-режим: векторный RAG и модель через OpenRouter
python3 days/day-33-support/service.py
```

Откройте **http://127.0.0.1:8033**. В AI-режиме задайте `OPENROUTER_API_KEY`
в окружении или в корневом `.env`. Ключ нужен для модели и эмбеддингов.
Модель — `deepseek/deepseek-chat`, переопределяется через `DAY33_MODEL`.
Без ключа AI-запрос вернёт понятную ошибку, а не выдуманный ответ.
Порт можно изменить: `--port 8034`. Сервер привязан только к loopback.

Разовый запрос CLI:

```bash
python3 days/day-33-support/service.py --demo \
  --user U-100 --ticket T-100 --question 'Почему не работает авторизация?'
```

## Три разных ответа на один вопрос

| Пользователь / тикет | Факт из MCP | Действие по документации |
|---|---|---|
| U-100 / T-100 | Business, SSO_REQUIRED | Использовать корпоративный SSO |
| U-200 / T-200 | Pro, ACCOUNT_LOCKED | Подождать 15 минут и восстановить пароль |
| U-300 / T-300 | Free, EMAIL_UNVERIFIED | Запросить письмо подтверждения |

Можно спросить без тикета: «Как экспортировать задачи?» или «Как пригласить
коллегу?». В AI-режиме ассистент учитывает тариф из CRM. Демо показывает
выдержки из документов и не выдаёт их за сгенерированный ответ модели.

## Как устроено

```text
HTTP / CLI → MCPClient → crm_mcp.py → data/crm.json
          → вопрос + код ошибки → Knowledge → docs/*.md
          → контекст CRM + найденные выдержки → OpenRouter → ответ с источниками
```

`get_support_context(user_id, ticket_id?)` проверяет существование пользователя
и принадлежность тикета **до** возврата данных. Сервис не передаёт клиенту или
модели весь JSON. Индексируются только документы продукта; пользователи и
тикеты в RAG не сохраняются. Новый запрос заново получает контекст по MCP.

В облаке переиспользуются `shared/index.py`, `shared/embeddings.py` и
`shared/llm.py`; структурные чанки и векторы сохраняются в `memory/day33-support/`
(gitignored). При изменении документации индекс перестраивается. Для изоляции
кэша можно задать `AI_ADVENT_SUPPORT_CACHE` до старта процесса. В демо используется
лексический поиск с приоритетом точного кода ошибки и извлечение текста.

## API

```bash
curl http://127.0.0.1:8033/health
curl http://127.0.0.1:8033/api/ask \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"U-200","ticket_id":"T-200","question":"Почему не работает авторизация?"}'
```

Ответ содержит `answer`, `mode`, `status`, `context`, `sources` (документ,
раздел, выдержка, score), `tools` (реальный MCP-вызов) и `seconds`.
В UI контекст и источники показаны отдельно. Ошибки — JSON `error.code/message`:
400 неверный ввод, 403 чужой тикет/Origin/Host, 404 неизвестный ID,
413 тело больше 16 КБ, 415 неверный Content-Type, 502 ошибка модели,
503 нет ключа/CRM недоступна/сервис занят. Вопрос ограничен 2000 символами.

## Проверки

```bash
python3 -m unittest discover -s days/day-33-support -p 'test_*.py' -v
python3 days/day-33-support/smoke.py
python3 days/day-33-support/smoke.py --live  # использует реальные API и платные токены
```

Тесты используют настоящий MCP-процесс и loopback HTTP. Модель в unit-тестах
заменена моками. `smoke.py --live` проверяет три причины авторизации через
HTTP, настоящий MCP, векторный индекс и модель. В CI реальная проверка запускается
только для PR из этого репозитория с `OPENROUTER_API_KEY`; fork получает автономные
тесты. Синтетические ответы и источники сохраняются в Actions artifact.

## Ограничения

Это локальная демонстрация консоли оператора, не production CRM. Переданный
`user_id` — выбранная учебная запись, не доказательство личности. Проверка
принадлежности тикета не заменяет аутентификацию; для реального сервиса нужны
серверная сессия, роли, tenant isolation и политика персональных данных.
Нет отправки писем, сброса паролей, изменения тарифа и закрытия тикетов.
При отсутствии знаний — предложение обратиться к оператору. Модель может ошибаться;
источники показаны для проверки человеком. Браузерную визуальную проверку в этой
сессии не проводили; HTTP и синтаксис UI проверяются отдельно.
