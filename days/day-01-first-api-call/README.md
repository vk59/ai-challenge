# День 1 — Первый запрос к LLM через API

## Задание

Минимальный код, который:
- отправляет запрос в LLM через API
- получает ответ
- выводит его в консоль или простой интерфейс (CLI / Web)

**Формат сдачи:** видео + код.

## Что сделано

Клиент к **DeepSeek API** (OpenAI-совместимый REST) на чистой стандартной библиотеке Python —
без `requests`, без SDK, без Flask. Ставить нечего, запрос собирается руками, поэтому видно
из чего он состоит: `POST https://api.deepseek.com/chat/completions`, заголовок
`Authorization: Bearer <ключ>` и JSON-тело с массивом `messages`.

Ответ приходит потоком (`stream: true`), поэтому текст печатается по мере генерации —
и в терминале, и в браузере.

| Файл | Что делает |
|------|-----------|
| [llm.py](llm.py) | сам HTTP-запрос к API + разбор ответа и ошибок |
| [main.py](main.py) | CLI: печатает ответ в консоль |
| [web.py](web.py) | HTTP-сервер на `http.server`: отдаёт страницу и стримит ответ |
| [ui.html](ui.html) | интерфейс в стиле окна macOS — вся вёрстка и скрипты |
| [app.py](app.py) | нативное окно macOS: тот же сервер + системный WebKit |
| [make_icon.py](make_icon.py) | рисует иконку приложения кодом, без картинок в репозитории |
| [build_app.sh](build_app.sh) | собирает `День 1.app` |

Интерфейс сделан «как нативное приложение»: окно со скруглениями и «светофором», системный
шрифт SF, пузыри сообщений как в Сообщениях, светлая и тёмная темы переключаются вслед за
системной настройкой. Всё на голом CSS, без единой внешней зависимости.

## Настройка

Файл `.env` в корне репозитория уже создан (в git он не попадает). Осталось вписать в него ключ
с https://platform.deepseek.com/api_keys:

```
DEEPSEEK_API_KEY=sk-...
```

Модель переключается там же: `deepseek-chat` (V3, быстрая) или `deepseek-reasoner` (R1, рассуждает).

## Запуск

Зависимостей нет — нужен только Python 3.10+. Всё запускается из этой папки:

```bash
cd days/day-01-first-api-call
```

### Приложение для macOS

Собрать (один раз):

```bash
./build_app.sh
```

Скрипт создаст venv с PyObjC в `~/Library/Application Support/AI Advent`, нарисует иконку,
скопирует код внутрь бандла и подпишет его. Запуск — двойным кликом по `dist/День 1.app`
или из терминала:

```bash
open "dist/День 1.app"
```

Это обычное окно Cocoa: своя иконка в доке, ⌘N — новый диалог, ⌘W — закрыть, ⌘Q — выйти.
Внутри тот же локальный сервер и та же страница, просто рисует её системный WebKit.

**Почему приложение живёт не в репозитории.** macOS не пускает программы в `~/Documents`
без явного разрешения (механизм TCC), а репозиторий лежит именно там. Запущенное из Finder
приложение падало ещё до старта — не мог прочитаться собственный Python из venv, причём
системного диалога «разрешить доступ» так и не появлялось: процесс внутри бандла — внешний
интерпретатор, и запрос не к чему привязать. Поэтому сборка складывает всё за пределы
защищённой папки:

- venv с PyObjC → `~/Library/Application Support/AI Advent/venv`
- код (`app.py`, `web.py`, `llm.py`, `ui.html`) → внутрь бандла
- копия `.env` → `~/Library/Application Support/AI Advent/.env`, права `600`

Источник правды остаётся в репозитории. **Поменяли ключ или код — пересоберите:**
`./build_app.sh`. Из терминала (`python3 web.py`, `python3 main.py`) всё работает напрямую
из репозитория, без копий и без пересборки.

### Интерфейс в браузере

```bash
python3 web.py
```

В консоли появится ссылка — открыть **http://127.0.0.1:8000** в браузере.
Ввести вопрос, `Enter` — отправить, `Shift+Enter` — перенос строки.
Остановить сервер: `Ctrl+C`.

Если порт занят, можно взять другой:

```bash
python3 web.py 8001
```

Что умеет окно: ответ печатается вживую, markdown (списки, **жирный**, блоки кода)
форматируется на лету, под ответом видно модель, время и потраченные токены.
Диалог помнит предыдущие реплики, кнопка «Новый диалог» в титлбаре очищает историю.

### CLI

```bash
python3 main.py "Объясни в двух предложениях, что такое REST API"
python3 main.py                 # спросит вопрос интерактивно
```

## Что показать на видео

1. Показать `.env.example` и сказать, что реальный ключ лежит в `.env` и в git не попадает
   (**сам ключ в кадр не выводить**).
2. Показать `llm.py` — где формируется URL, заголовок и тело запроса.
3. Запустить CLI с вопросом, показать как ответ печатается в консоли.
4. Запустить `web.py`, задать вопрос в браузере, показать стриминг ответа.
5. Опционально: показать обработку ошибки — стереть ключ в `.env` и получить внятное
   сообщение вместо трейсбека.
