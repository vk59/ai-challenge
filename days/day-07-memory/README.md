# День 7 — Сохранение контекста

## Задание

Добавить агенту сохранение контекста: хранить историю диалога в JSON или SQLite,
при перезапуске загружать её обратно и продолжать разговор так, как будто агент
не выключался.

**Формат сдачи:** видео + код.

## Главное, что выяснилось по дороге

Задание звучит как «допишите историю на диск», но при первой же попытке это сделать
выясняется, что **«память» в дне 6 была одним понятием, а должна быть двумя**:

| | что это | ограничено | что с ней делает `_trim()` |
|---|---|---|---|
| **Окно контекста** | что уезжает в модель в следующем запросе | `memory_turns = 10` пар | подрезает |
| **Архив** | что лежит на диске и переживает выключение | ничем | не трогает |

В дне 6 они совпадали, поэтому подрезка означала **потерю**: одиннадцатая пара реплик
вытесняла первую, и первая исчезала навсегда. Теперь подрезка касается только окна —
из архива не пропадает ничего.

Разделять их обязательно, и вот почему. Простое «загрузим при старте всё, что сохранили»
ломается на втором дне использования: в модель уедет диалог на тысячу реплик, счёт за
токены вырастет во столько же раз, а потом запрос просто упрётся в потолок контекста.
Поэтому при запуске с диска поднимаются **последние десять пар**, а остальное остаётся
архивом: его видит человек в ленте, но не видит модель.

В интерфейсе это показано буквально — реплики вне окна нарисованы полупрозрачными,
с чертой «отсюда начинается окно контекста»:

```
диалог «default» · окно 10/10 · архив 47
```

## Что изменилось в коде

Хранилище — новый файл [shared/memory.py](../../shared/memory.py). Агент получил
**необязательный** параметр `store`:

```python
Agent(name="Помощник")                                  # день 6: память умирает с процессом
Agent(name="Помощник", store=SqliteStore())             # день 7: переживает перезапуск
```

Без `store` поведение дня 6 не изменилось ни на байт — тот день остаётся рабочим
артефактом. Это та же линия, что и с [shared/llm.py](../../shared/llm.py), который так же
прирастал возможностями от дня к дню, не ломая предыдущие.

Новое в интерфейсе агента:

```python
agent.transcript()        # весь архив — для экрана, а не для модели
agent.switch("работа")    # перейти в другой диалог, текущий остаётся на диске
agent.archived            # сколько пар лежит на диске
agent.reset()             # забыть — теперь и на диске тоже
```

## JSON или SQLite

Задание разрешает любое. Сделаны оба, переключаются флагом `--store`, потому что
разница между ними — это ровно то, что происходит при дозаписи одной реплики:

```python
# JsonStore.append   прочитать файл целиком → добавить в список → записать файл целиком
# SqliteStore.append INSERT одной строки
```

Отсюда всё остальное:

| | JSON | SQLite |
|---|---|---|
| Дозапись реплики | переписывает весь файл | вставляет одну строку |
| Стоимость записи | растёт с размером архива | не зависит от размера |
| Атомарность | делаем сами: временный файл + `os.replace` | транзакция движка |
| Параллельные записи | свой `threading.Lock` | блокировки движка |
| Выборка последних N | прочитать всё, отрезать хвост | `ORDER BY id DESC LIMIT N` |
| Прочитать глазами | `cat memory/default.json` | нужен клиент sqlite3 |
| Правка руками | открыть в редакторе | SQL |

Ни то ни другое не тянет зависимостей: `json` и `sqlite3` — стандартная библиотека.
В репозитории по-прежнему нет ни одного `pip install`.

**По умолчанию SQLite.** JSON оставлен не для галочки: пока архив маленький, читаемый
файл полезнее скорости, и на видео его удобно показать. Но именно поэтому важно понимать,
за что платишь, — числа ниже.

### Чего стоит «переписать файл целиком»

Замер лежит в [bench.py](bench.py), запускается без ключей и без сети:

```bash
python3 bench.py
```

Стоимость записи **одной** реплики в зависимости от того, сколько их уже в архиве:

| реплик в архиве | JSON, мс | SQLite, мс | разница |
|---:|---:|---:|---:|
| 10 | 0.22 | 0.26 | — |
| 100 | 0.59 | 0.30 | 2× |
| 500 | 1.68 | 0.64 | 3× |
| 1 000 | 3.45 | 0.35 | 10× |
| 2 000 | 7.07 | 0.39 | 18× |
| 4 000 | 14.12 | 0.35 | **40×** |

Поднять окно контекста (20 последних реплик) из архива в 4000 — тот самый запрос,
который выполняется при каждом старте:

| | JSON | SQLite |
|---|---:|---:|
| Чтение окна | 4.75 мс | 0.11 мс |
| Размер архива на диске | 1954 КБ | 1868 КБ |

Абсолютные числа зависят от машины и диска, у вас будут свои. Важна не они, а форма.

Обратите внимание на форму: у SQLite колонка плоская, у JSON растёт линейно с размером
архива. А поскольку архив растёт с каждой репликой, суммарное время записи диалога у JSON
растёт **квадратично** — та же ловушка, из-за которой в дне 6 появилось ограничение
окна контекста, только теперь не по токенам, а по диску.

## Мелочи, которые видно только когда попробуешь

**Запись по факту события, а не при выходе.** Приложения закрывают не только пунктом меню
«Выйти»: ⌘Q, Ctrl+C, разряженная батарея, kill -9. Поэтому реплика уходит на диск сразу
после того, как получена, а не в обработчике завершения — его может не быть.

**Оборванный ответ тоже сохраняется.** В `Agent.stream()` запись стоит в `finally`:

```python
finally:
    if chunks:
        self._remember(message, "".join(chunks), ...)
```

Без этого прерванный на середине ответ (Ctrl+C, закрытая вкладка, обрыв сети) пропал бы
вместе с вопросом, и после перезапуска диалог был бы с дырой: вопрос есть, ответа нет.

**Атомарная запись JSON.** Пишем во временный файл рядом и подменяем через `os.replace`.
Прямая запись в существующий файл означала бы, что обрыв на середине оставит обрезанный
JSON — то есть потерю **всего** диалога, а не последней реплики.

**Окно не должно начинаться с ответа модели.** Срез последних двадцати реплик может
разрезать пару пополам, и тогда диалог для API начинается с `assistant`. Формально
допустимо, но выглядит так, будто модель заговорила первой; висящий хвост отрезается.

**«Забыть» обязано стирать диск.** Иначе кнопка врёт: после перезапуска забытое вернулось
бы. Поэтому `reset()` чистит и окно, и архив, а для «начать новый разговор, не теряя
старый» есть отдельная кнопка — она создаёт новую сессию.

**Хранилище у приложения живёт вне бандла.** `./build_app.sh` собирает `.app` заново,
и если бы история лежала внутри, каждая пересборка стирала бы переписку. Плюс macOS
не пускает приложения в `~/Documents` без разрешения TCC. Поэтому архив уезжает
в `~/Library/Application Support/AI Advent/memory`, путь передаётся через
`AI_ADVENT_MEMORY_DIR` — тем же приёмом, которым в дне 6 передавался `.env`.

**Веб-сервер многопоточный.** `ThreadingHTTPServer` означает, что две вкладки могут
писать одновременно. У SQLite это забота движка, у JSON — наш `threading.Lock`, иначе
две реплики затрут друг друга.

## Запуск

Зависимостей нет, нужен Python 3.10+ и ключ в `.env` (см. корневой README).

### Терминал

```bash
cd days/day-07-memory
python3 cli.py                      # продолжить диалог «default»
python3 cli.py --session работа     # другой диалог
python3 cli.py --store json         # хранить в JSON вместо SQLite
python3 cli.py --dir /tmp/память    # другой каталог хранилища
```

Команды в чате: `/стат`, `/история`, `/сессии`, `/сброс`, `/роль`, `/журнал`, `/выход`.

### Окно в браузере

```bash
python3 web.py                      # http://127.0.0.1:8000
python3 web.py 9000 --store json
```

### Нативное приложение

```bash
./build_app.sh
open "dist/День 7.app"
```

### Где лежит история

```bash
ls memory/                          # каталог по умолчанию, в git не попадает
sqlite3 memory/agent.db "SELECT session, role, substr(content,1,40) FROM turns LIMIT 5;"
cat memory/default.json             # если запускали с --store json
```

## Проверка задания

Тридцать секунд в терминале:

```bash
python3 cli.py
вы › меня зовут Иван, запомни
вы › ^D                             # Ctrl+D — процесс убит, оперативная память очищена

python3 cli.py                      # тот же файл, новый процесс
вы › как меня зовут?
```

Агент отвечает «Иван», а сверху терминала напечатан восстановленный хвост прошлого
разговора. То же самое в нативном окне: ⌘Q и повторный запуск.

## Что показать на видео

1. **Задание, буквально.** В окне сказать «меня зовут Иван», закрыть приложение на ⌘Q
   (процесса больше нет), открыть заново — переписка на месте, спросить «как меня зовут?»
   → помнит. Это ответ на задание, дальше идут детали.
2. **Где это лежит.** `sqlite3 memory/agent.db "SELECT ..."` или `cat memory/default.json`
   рядом с окном: вот те самые реплики, обычный файл на диске.
3. **Окно контекста ≠ архив** — центральная мысль дня. Показать `/история` в CLI:
   пометки `⟨вне окна⟩` на старых репликах. Объяснить, почему нельзя просто загрузить
   всё: токены и потолок контекста. В окне это видно как полупрозрачные сообщения
   и черта «отсюда начинается окно контекста».
4. **Почему SQLite, а не JSON** — запустить `python3 bench.py` вживую. Колонка SQLite
   плоская, JSON растёт с размером архива, потому что переписывает файл целиком.
5. **Две реализации одного интерфейса.** `--store json` и `--store sqlite` на одном и том
   же `cli.py`: агент не знает, куда пишет. Показать, что `Agent` работает со `Store`,
   а не с файлом.
6. **Что ломается, если делать наивно.** Три места: запись при выходе (⌘Q, kill -9 —
   обработчика может не быть), запись поверх файла без `os.replace` (обрыв → битый JSON →
   потерян весь диалог), `reset()` без стирания диска (кнопка врёт, забытое возвращается
   после перезапуска).
7. **Совместимость.** День 6 запускается и работает как раньше: `store` — необязательный
   параметр, без него агент ведёт себя ровно как вчера.
