# День 6 — Первый агент

## Задание

Реализовать агента, который принимает запрос, отправляет его в LLM, получает ответ
и выводит результат в интерфейсе.

**Важно:** агент должен быть отдельной сущностью, а не просто одним вызовом API. Логика
запроса и ответа — инкапсулирована в агенте.

**Формат сдачи:** видео + код.

## Чем это отличается от дня 1

В дне 1 была **функция**: отправил строку, получил строку. Никакого состояния, каждый вызов
сам по себе. Агент — это **объект со своей жизнью**:

| | День 1 (`ask`) | День 6 (`Agent`) |
|---|---|---|
| Роль | нет | системный промпт: кто он и как отвечает |
| Память | нет | помнит диалог, сам собирает список сообщений |
| Настройки | передаются при каждом вызове | свои: модель, температура, глубина памяти |
| Учёт | нет | токены, время и журнал обращений за сессию |
| Жизненный цикл | нет | `reset()`, подрезка старых реплик |

## Где проходит граница

Весь код, знающий про HTTP и формат API, заперт в [shared/llm.py](../../shared/llm.py).
Агент в [shared/agent.py](../../shared/agent.py) знает про транспорт, но наружу отдаёт
только четыре вещи:

```python
agent.ask("привет")      # ответ целиком
agent.stream("привет")   # ответ кусками
agent.reset()            # забыть диалог
agent.stats              # сколько потрачено
```

Интерфейсы не знают ни про HTTP, ни про JSON, ни про список `messages`, ни про токены.

**Как это проверить, а не поверить на слово.** В [cli.py](cli.py) и [web.py](web.py) нет
ни одного импорта из `llm` и ни одного сетевого вызова:

```
$ grep -E "urlopen|Bearer|chat/completions" cli.py web.py ui.html
(ничего)
```

Импорты в интерфейсах: `shutil`, `sys`, `textwrap`, `pathlib`, `json`, `http.server`,
`urllib.parse` — и `agent`. Всё. `urllib.parse` там для разбора собственных маршрутов
сервера, к API отношения не имеет.

**Второе доказательство — то, что отправляет браузер.** В дне 1 страница присылала всю
историю диалога с каждым вопросом, потому что помнить было некому:

```js
body: JSON.stringify({ prompt, history })     // день 1
body: JSON.stringify({ message })             // день 6
```

Теперь уходит одна строка. История живёт в агенте, и браузер о ней вообще не знает.
Кнопка «Новый диалог» тоже не чистит ничего локально — она дёргает `POST /reset`,
и забывает сам агент.

**Третье — два интерфейса над одним агентом.** CLI и веб написаны независимо, оба работают
с одним объектом и ни один не содержит логики общения с моделью. Если бы логика протекала
наружу, её пришлось бы дублировать.

## Из чего состоит агент

| Файл | Что делает |
|------|-----------|
| [../../shared/agent.py](../../shared/agent.py) | сам агент: роль, память, настройки, статистика, журнал |
| [../../shared/llm.py](../../shared/llm.py) | транспорт: HTTP-запрос к API |
| [cli.py](cli.py) | чат в терминале |
| [web.py](web.py) | HTTP-сервер: отдаёт страницу и стримит ответ агента |
| [ui.html](ui.html) | окно в стиле macOS + строка состояния агента |
| [app.py](app.py) | то же окно как нативное приложение |
| [build_app.sh](build_app.sh) | сборка `День 6.app` |

### Память — это не магия

Модель между запросами не помнит ничего. Весь диалог каждый раз отправляется заново,
целиком. Агент просто хранит список реплик и подставляет его сам:

```python
self._history.append({"role": "user", "content": question})
self._history.append({"role": "assistant", "content": answer})
```

### Почему память ограничена

`memory_turns=10` — не прихоть. Каждый запрос тащит с собой всю переписку, поэтому
без ограничения расход токенов растёт **квадратично**: десятая реплика оплачивает
девять предыдущих, сотая — девяносто девять. Агент держит последние десять пар
и подрезает старое.

В строке состояния окна видно `память 3/10` — сколько занято. Когда упирается в потолок,
счётчик краснеет: это момент, когда агент начал забывать начало разговора.

## Запуск

Зависимостей нет, нужен Python 3.10+ и ключ в `.env` (см. корневой README).

### Терминал

```bash
cd days/day-06-first-agent
python3 cli.py
python3 cli.py --role "Ты ворчливый сисадмин, отвечаешь односложно"
```

Команды в чате: `/стат`, `/сброс`, `/роль`, `/журнал`, `/выход`.

### Окно в браузере

```bash
python3 web.py            # http://127.0.0.1:8000
```

### Нативное приложение

```bash
./build_app.sh
open "dist/День 6.app"
```

Устройство бандла и почему рантайм лежит вне репозитория — разобрано в
[README дня 1](../day-01-first-api-call/README.md).

## Что показать на видео

1. [shared/agent.py](../../shared/agent.py) — класс `Agent`: роль, память, настройки,
   статистика. Это и есть «отдельная сущность» из задания.
2. Показать `grep` по интерфейсам: ни одного импорта из `llm`, ни одного сетевого вызова.
   Инкапсуляция не на словах.
3. Открыть рядом `web.py` дня 1 и дня 6: `{prompt, history}` против `{message}`.
   Браузер перестал таскать историю — её взял на себя агент.
4. В окне: сказать «меня зовут Иван», следующим сообщением спросить «как меня зовут?» —
   агент помнит. Нажать «Новый диалог», спросить снова — забыл.
5. Тот же агент в CLI: `/стат` и `/журнал` показывают его внутреннюю кухню.
6. Строка состояния: `память 3/10` — и рассказать, почему потолок вообще нужен.
