# Сценарий видео — День 21. Тридцать секунд

Показывается одно: **две стратегии нарезки на одном запросе, и структурная
находит точнее.**

## Перед записью

```bash
cd ~/Documents/ai-challenge/days/day-21-indexing
./build_app.sh && open "dist/День 21.app"
```

**Если приложение уже открыто — сначала ⌘Q.**

Индекс внутри приложения должен быть уже собран: нажмите «Собрать индекс»
до записи и дождитесь, пока в карточках слева появятся числа. Сборка с нуля
идёт полминуты — в кадре её ждать не надо.

## Раскадровка

| Время | Что делаешь | Что в кадре |

| 0:22–0:30 | показываешь итог снизу | hit@1 4/14 против 10/14, MRR 0.449 против 0.774 |

## Что сказать

> «Двести страниц документов и кода нарезаны двумя способами: окном по
> тысяче двести знаков и по структуре — заголовкам и определениям. Один
> запрос, две выдачи. Смотрите на строку «раздел»: слева у куска только
> номера знаков, справа — название раздела, в который он попал. И это не
> косметика: прогоняю четырнадцать вопросов с заранее известным ответом —
> структурная нарезка находит нужное первым в десяти случаях против
> четырёх, MRR ноль семьсот семьдесят четыре против ноль четыреста сорок
> девять.»

## Главный кадр

Две строки «раздел» рядом: `знаки 2964–4160` против `Главные грабли: macOS
не пускает приложение к репозиторию`. Разница между стратегиями в одном
взгляде.

## Если добавляете 20 секунд

**Предел смыслового поиска.** В строку поиска:

```
какими сообщениями обмениваются при установлении связи по стандартному вводу-выводу
```

Нужный файл не находится. Потом:

```
какими сообщениями обмениваются при рукопожатии MCP
```

Находится.

> «Одно техническое слово — и файл поднимается в топ. Вопрос вообще без
> терминов англоцентричная модель по русскому тексту не вытягивает.»

**Цена в терминале:**

```bash
python3 build.py
```

> «Полная сборка двухсот страниц — шесть десятых цента. Повторная
> бесплатная: векторы в кэше.»
