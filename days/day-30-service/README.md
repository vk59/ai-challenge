# День 30 — Локальная LLM как приватный сервис

## Задание

Развернуть локальную LLM как сервис на VPS или домашнем сервере, с HTTP API
и возможностью чата. Проверить доступ по сети, устойчивость при нескольких
запросах и базовые ограничения.

## Домашний сервер, а не VPS

Задание разрешает оба варианта, и выбор здесь содержательный. VPS с памятью
под модель стоит заметных денег в месяц, а смысл локальной модели — не
платить за токены и не отдавать данные наружу. Хостить её на чужой машине
значит потерять половину смысла.

Поэтому сервер — тот же ноутбук: M4 Pro, 48 ГБ, он и так работает.

## Шлюз, а не голый Ollama

Ollama умеет слушать сеть сам — `OLLAMA_HOST=0.0.0.0`. Так делать нельзя:
у него нет ни ключей, ни ограничений. Открыть его в сеть значит отдать
свою машину любому, кто просканирует порты: он сможет грузить её запросами,
скачивать и удалять модели.

Поэтому Ollama остаётся на `127.0.0.1`, а наружу смотрит шлюз:

```
телефон ──► 192.168.1.122:8080 ──► 127.0.0.1:11434
            шлюз: ключ,              Ollama
            лимиты, очередь
```

| что добавляет шлюз | зачем |
|---|---|
| ключ `Authorization: Bearer` | без него сервис в сети — общий |
| лимит 30 запросов в минуту на ключ | один клиент не займёт машину целиком |
| очередь, 1 запрос за раз | два запроса к одной модели идут не быстрее, а вдвое дольше каждый |
| потолок промпта 24000 знаков | лучше понятный отказ, чем молчаливое обрезание |
| `/health` без ключа | мониторингу секреты ни к чему, ничего чувствительного там нет |

Эндпоинт **OpenAI-совместимый**, поэтому к сервису подходит любой клиент.
Наш собственный `shared/llm.py` подключился без единой правки:

```python
SERVICE = Provider("Home", "http://192.168.1.122:8080/v1",
                   "AI_ADVENT_SERVICE_KEY", "см. ключ в memory/")
ask("Скажи ровно: через свой сервис", provider=SERVICE)
# → через свой сервис
```

## Проверки

```bash
python3 loadtest.py --url http://192.168.1.122:8080
python3 loadtest.py --clients 8 --each 3
python3 loadtest.py --only limits
```

### Доступ по сети

```
✓ /health отвечает: модель qwen2.5:3b, Ollama жив
✓ без ключа: 401 unauthorized
✓ с ключом: 200 за 0.08с
```

### Устойчивость

Шесть клиентов по два запроса разом, все к одной модели:

```
всего 12 запросов за 12.9с
✓ успешных 12
задержка: медиана 5.97с, быстрее 1.27с, медленнее 6.55с
✓ сломанных ответов нет
очередь доходила до 5
```

Главное тут не «успешных 12», а **разброс 1.27–6.55 секунды**. Это и есть
цена очереди: первый запрос обслуживается сразу, шестой ждёт впереди себя
пятерых. Параллелить нечего — модель одна, и попытка пустить всех сразу
сделала бы хуже каждому.

Критерий успеха здесь — не скорость, а то, что **сервис либо отвечает,
либо честно отказывает**. Пятисоток и оборванных соединений нет.

### Ограничения

```
✓ длинный промпт: 413 context_too_long
  «Промпт 26000 знаков, потолок 24000. Сократите контекст:
   молча обрезать запрос сервис не будет.»
✓ лимит сработал на 17-м запросе, Retry-After: 47с
```

Отказ должен говорить, что делать дальше. `Retry-After` в заголовке —
чтобы клиент не гадал, а подождал ровно столько, сколько нужно.

## Автозапуск

```bash
./install_service.sh --lan        # поднять и поставить в автозапуск
./install_service.sh --remove     # снять
launchctl list | grep aiadvent    # состояние
```

Служба переживает закрытие терминала и поднимается при входе в систему.
Без `--lan` слушает только эту машину — так безопаснее по умолчанию.

### Три грабли при установке службы

**macOS не пускает службу к `~/Documents`.** Та же ловушка TCC, что
в дне 17 с приложением, только теперь с launchd:

```
can't open file '.../ai-challenge/days/day-30-service/service.py':
Operation not permitted
```

Разрешение выдано терминалу, а не службе. Решение прежнее: код копируется
в `~/Library/Application Support/AI Advent/service` и запускается оттуда.

**`/usr/bin/env python3` в launchd — это не тот python3.** Служба
подхватила интерпретатор из Xcode версии 3.9 и упала на аннотации
`str | None` ещё до первой строки работы. Теперь установщик прописывает
полный путь к найденному в терминале интерпретатору и сразу проверяет,
что он не старше 3.10.

**Служба завела собственный ключ.** Запущенная вручную, она пишет ключ
в `memory` репозитория; поставленная в автозапуск — рядом с собой.
Получилось два ключа, и проверки честно отвечали 401 на всё. Теперь
установщик передаёт службе общий каталог памяти, а нагрузочный тест
ищет ключ в обоих местах.

## Чат с телефона

`http://192.168.1.122:8080/chat` открывается в браузере телефона: ключ
вводится один раз и хранится в localStorage этого браузера, под каждым
ответом видно секунды, токены и сколько запросов израсходовано за минуту.
В настройках — живая статистика сервиса: очередь, медиана, отказы.

## Чего здесь нет и почему

**HTTPS.** В локальной сети за роутером трафик не выходит за пределы
квартиры, а самоподписанный сертификат добавил бы возни с доверием на
каждом устройстве. Если выставлять сервис в интернет — нужен и сертификат,
и обратный прокси, и это уже другая задача.

**Выставления наружу.** `--lan` открывает сервис в локальную сеть, не
в интернет. Пробрасывать порт на роутере я не советую: ключ один, его
утечка открывает машину, и защиты от подбора здесь нет.

**Нескольких ключей и учёта по пользователям.** Для домашнего сервиса
на одну семью это лишнее усложнение; лимит считается на ключ, и этого
хватает.

## Запуск

```bash
cd days/day-30-service

python3 service.py                      # только эта машина
python3 service.py --host 0.0.0.0       # в локальную сеть
python3 service.py --model qwen2.5:7b
./install_service.sh --lan              # в автозапуск

python3 loadtest.py --url http://192.168.1.122:8080
```

Нужен работающий Ollama с моделью:

```bash
brew services start ollama
ollama pull qwen2.5:3b
```

Ключ появится при первом запуске и ляжет в файл с правами 600.
