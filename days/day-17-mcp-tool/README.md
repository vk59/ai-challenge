# День 17 — Первый инструмент MCP

## Задание

Реализовать свой MCP-сервер вокруг любого API, сделать регистрацию инструмента,
описание входных параметров и возврат результата. Подключить к агенту, вызвать
из приложения, получить и использовать результат.

## Что выбрано и почему

**Git и GitHub** — он прямо назван в примерах задания, и данных у нас много
и они свои: двадцать коммитов с подробными сообщениями за семнадцать дней.
Ключей не нужно, `gh` уже авторизован.

Главное — на видео это замыкает всю историю: агент получает доступ
к **летописи собственной разработки** и отвечает про девятый день не выдумкой,
а выпиской из коммита.

## Три части, которых не было

День 16 научил клиента разговаривать по MCP. Чтобы агент начал **пользоваться**
инструментами, понадобилось достроить три вещи.

**1. Сервер вокруг git** — [server.py](server.py), пять инструментов:

| инструмент | параметры | что отдаёт |
|---|---|---|
| `day_summary` | `day` (обязательный) | коммит дня целиком и список файлов |
| `search_commits` | `query`, `limit` | коммиты по слову в сообщении |
| `file_history` | `path` | в каких коммитах менялся файл |
| `repo_stats` | — | коммиты, дни, файлы, строки |
| `github_info` | — | видимость и адрес через `gh` |

**2. Мост MCP → модель** — [shared/tools.py](../../shared/tools.py).
Формы описаний близкие, но не совпадают:

```
MCP                          OpenAI
{name, description,    →     {type: "function", function: {
 inputSchema}                   name, description, parameters}}
```

Он же держит несколько серверов сразу и разводит имена по префиксам:
`git__day_summary`. Иначе два сервера с инструментом `search` передрались бы.

**3. Цикл вызовов в агенте** — [shared/agent.py](../../shared/agent.py),
метод `_ask_with_tools`:

```
→ вопрос + описания инструментов
← «вызови day_summary(day=9)»        finish_reason=tool_calls
→ результат вызова, ролью tool
← готовый ответ человеку             finish_reason=stop
```

Кругов может быть несколько: модель вправе посмотреть результат и позвать
следующий инструмент. Потолок (`max_tool_rounds = 4`) обязателен — без него
пара неудачных вызовов закручивается в бесконечный цикл за ваши деньги.

## Как это выглядит живьём

Вопрос в окне: **«Что делалось в тринадцатый день?»**

```
🔧 git__day_summary({'day': 13}) → 2802 знаков, 0.09 с
   День 13, коммит 1ced40f0 от 2026-09-21

Ответ:
**День 13** (коммит `1ced40f0`, 2026-09-21) — «состояние задачи как конечный автомат»
- Этап задачи — не свободное поле, а состояния с разрешёнными переходами
- Модель только *предлагает* этап, решение принимает код
- Состояние хранится в отдельной таблице: переживает ⌘Q
```

Агент **сам** решил, какой инструмент нужен. В ленте видно плашку вызова —
что дёрнули, с какими аргументами, сколько вернулось и за сколько.

Ещё пример, числа настоящие:

```
🔧 git__repo_stats() → 150 знаков
→ «20 коммитов, 20 979 строк, 101 файл под версией»
```

## Четыре места, где спотыкаются

**`content` приходит `null`.** Когда модель просит инструменты, текста в ответе
нет вовсе. Раньше `llm.py` брал `choice["message"]["content"]` напрямую
и получил бы `None` там, где ждут строку. Теперь пустая строка — честнее,
текста действительно нет.

**Реплику модели нужно вернуть в разговор целиком.** Сообщение с `tool_calls`
обязано попасть в историю перед результатами: иначе следующий запрос ссылается
на вызовы, которых в истории нет, и API отказывает.

**Ошибка инструмента не должна ронять разговор.** Если сервер отказал или
аргументы не разобрались, модель узнаёт об этом текстом и пробует иначе.
Исключение наружу — худшее, что тут можно сделать.

**Внутри собранного `.app` репозитория нет.** `server.py` лежит в `Resources/`,
и путь «на два уровня вверх» указывает не туда. Поэтому корень задаётся
снаружи, через `AI_ADVENT_REPO` — `build_app.sh` прокидывает его в launcher.
Поймано при сборке, до запуска.

## Запуск

```bash
cd days/day-17-mcp-tool

python3 ask.py "Что я делал в девятый день?"   # в терминале
python3 ask.py --tools                          # только список инструментов
python3 web.py                                  # окно: http://127.0.0.1:8000
./build_app.sh && open "dist/День 17.app"       # нативное приложение
```

В окне справа — список инструментов, полученных от MCP-сервера. Каждый вызов
появляется в ленте по мере выполнения: агенту передан колбэк `on_tool`,
и события идут в браузер потоком, а не пачкой в конце.
