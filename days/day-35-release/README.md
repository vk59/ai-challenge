# День 35 — Release Desk

## Какую задачу решаем

Автоматизируем **подготовку релиза ai-challenge**: вместо ручного просмотра Git
сервис собирает изменения, готовит release notes, риски и список проверок.
Результат — Markdown-пакет, который можно приложить к PR, задаче или релизу
после проверки человеком.

## Как участвует AI

1. Сервис читает реальную Git-историю: base/head SHA, коммиты, файлы и diff.
2. Прямой DeepSeek получает цель и evidence, формулирует изменения для пользователей,
   подтверждённые риски и предлагаемые проверки. Это генерация моделью.
3. Сервис проверяет JSON и ссылки каждого highlight/risk на настоящие коммиты.
   Существование ссылки не доказывает истинность каждой формулировки AI.
4. Пакет показывается, скачивается или сохраняется в Markdown без повторной генерации.

## Запуск

Python 3.10+, Git, стандартная библиотека; устанавливать зависимости не нужно.
Из корня репозитория:

```bash
python3 days/day-35-release/web.py
```

Откройте **http://127.0.0.1:8035**, задайте base/head (SHA, ветка или тег) и цель,
нажмите **«Подготовить релиз»**. Вкладки: Release notes, Git evidence, Markdown.
**«Сохранить пакет»** создаёт ровно показанный Markdown в
`memory/day35-release/exports/`; **«Скачать .md»** скачивает тот же текст.

Нужен `DEEPSEEK_API_KEY` в окружении или корневом `.env`.
`AI_ADVENT_ENV_FILE` указывает другой файл окружения при работе из worktree.
`DAY35_MODEL` меняет модель; по умолчанию `deepseek-chat`.

```bash
python3 days/day-35-release/web.py --repo /absolute/project --port 8035
# Явная демонстрация без модели, с настоящими Git-данными:
python3 days/day-35-release/web.py --demo
```

По умолчанию `origin/main~1..origin/main`, при отсутствии origin/main —
`HEAD~1..HEAD`. Для репозитория с одним коммитом сначала нужен второй коммит:
одинаковые base/head отклоняются. Сервис не выполняет fetch: remote refs нужно
обновлять штатным Git при необходимости.

## Воспроизведение и проверки

```bash
python3 -m unittest discover -s days/day-35-release -p 'test_*.py' -v
python3 days/day-35-release/smoke.py
python3 days/day-35-release/smoke.py --live --output /tmp/day35-evidence
```

Smoke использует реальный checkout через HTTP: Git → AI → preview → save →
readback. `--base`/`--head` фиксируют диапазон. Без `--output` экспорт временный.
CI проверяет offline-тесты, demo и настоящий DeepSeek с существующим Actions
secret `DEEPSEEK_API_KEY`; Markdown и evidence сохраняются как artifact.

## Границы

Сервис готовит материалы. Тесты, сборка, тег, GitHub Release, выкладка и публикация
в стор не выполняются. Чеклист — что нужно сделать перед релизом.

Git читается по неизменяемым SHA; base должен быть предком head. Незакоммиченные
файлы не отправляются модели. Код checkout не исполняется. Данные репозитория
считаются недоверенными инструкциями.

До 100 коммитов, 80 файлов, 60000 символов diff; превышение — явная ошибка.
Фильтр дня 32 разрешает Markdown, Python, JSON, YAML и TOML. Другие типы,
бинарные файлы, файлы больше 120 КБ и распознаваемые секреты исключаются;
частичное покрытие и список пропусков видны в UI и Markdown. Эвристика не
распознаёт все возможные секреты: выбирайте разрешённый к отправке диапазон.

Loopback HTTP, Host/Origin, bounded JSON, один запуск/экспорт за раз,
до 8 задач в памяти. После перезапуска/вытеснения задачи её download недоступен;
сохранённый Markdown остаётся на диске. Повторное сохранение идемпотентно,
чужой существующий файл не перезаписывается.
