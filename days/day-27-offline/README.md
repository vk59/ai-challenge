# День 27 — Интеграция локальной LLM в приложение

## Задание

Интегрировать локальную модель в реальное приложение (CLI, бот, веб —
на выбор). Приложение отправляет запросы в локальную LLM, получает
и отображает ответы, **работает без облачных моделей**.

## Чего не хватало после дня 26

В дне 26 окно считалось локальным: модель отвечала через Ollama,
в подписи стояло `qwen2.5:3b`. Но на **каждую реплику уходил один запрос
в OpenRouter** — за вектором вопроса для поиска по индексу. Эмбеддинги
оставались облачными, и утверждение «без облачных моделей» было неправдой.

Проверяется это за минуту, если подменить сетевой вызов счётчиком:

```
задаю вопрос, которого нет в кэше векторов…
  ⚠ ОБРАЩЕНИЕ В ОБЛАКО: 1 кусков на openai/text-embedding-3-small
  обращений в облако за одну реплику: 1
```

Содержание дня — закрыть эту дыру и **доказать**, что её нет.

## Эмбеддинги на своей машине

У Ollama есть `/api/embed`. Добавлен второй бэкенд, переключается
переменной окружения:

```bash
AI_ADVENT_EMBEDDINGS=local python3 ../day-21-indexing/build.py
```

Индексы раздельные (`index.db` и `index-local.db`) — векторы разных
моделей несравнимы, 1536 измерений против 1024, и класть их в одну
таблицу значит получить поиск, который молча возвращает мусор.

### Модель выбрана по замеру, а не по популярности

Сначала взял `nomic-embed-text` — самый очевидный выбор. И получил
картину, в которой порог отказа провести негде:

| группа вопросов | nomic-embed-text | bge-m3 | облако |
|---|---|---|---|
| свои (ответ есть) | 0.769 … 0.886 | **0.558 … 0.678** | 0.402 … 0.655 |
| чужие (тема другая) | 0.690 … **0.792** | 0.277 … **0.516** | 0.154 … 0.370 |
| зазор | **нет**, перекрытие | есть | есть |

У `nomic` чужие вопросы доходят до 0.792, а свои начинаются с 0.769 —
распределения перекрываются, и отказ «не знаю» из дня 24 становится
невозможен. Модель всему ставит высокую похожесть.

Проверил гипотезу про префиксы: `nomic` обучен с `search_query:` и
`search_document:`, без них качество должно падать. Не помогло — разрыв
на контрольной паре был 0.107, с префиксами стал 0.100.

`bge-m3` разводит вчетверо лучше: 0.278 против 0.107. Взял её.

### Порог теперь зависит от бэкенда

```python
ABSTAIN_BY_BACKEND = {"cloud": 0.39, "local": 0.54}
```

Перенести 0.39 на локальные векторы нельзя — у них своя шкала. Это та же
ошибка, что перенести температуру по Фаренгейту в Цельсий, не пересчитав.

## Что стоил переезд

```bash
python3 compare_backends.py
```

| бэкенд | первым | топ-5 | топ-20 | MRR | мс | цена сборки |
|---|---|---|---|---|---|---|
| cloud | 6/10 | 9/10 | 10/10 | 0.736 | 67 | $0.006 |
| local | 6/10 | **10/10** | 10/10 | **0.745** | **49** | **$0** |

Ничего не стоил. Локальные эмбеддинги не хуже по качеству, быстрее
(нет сетевого round-trip) и бесплатны. Но это верно **только для
выбранной модели** — с `nomic` офлайн обошёлся бы потерей механизма
отказа.

## Доказательство, а не обещание

```bash
python3 offline_proof.py          # должно пройти
python3 offline_proof.py --cloud  # должно провалиться
```

Сеть не просто не используется — она физически закрыта: подменяется
`socket.socket.connect`, соединения на `127.0.0.1` проходят, любое
другое поднимает исключение с адресом, куда пытались пойти.

```
Закрываю сеть: наружу нельзя, 127.0.0.1 можно.

  1. Какая стратегия нарезки документов победила…    источников 1
  2. А на сколько именно?                            источников 2, раскрыт
     искал: На сколько именно стратегия нарезки по структуре победила?
  3. Какая столица Австралии?                        ОТКАЗ по порогу

Сеть была закрыта весь диалог. Попыток выйти наружу: 0.
```

**Проверка умеет проваливаться** — иначе ей грош цена. С облачными
эмбеддингами:

```
  ✗ попытка соединения с 2606:4700::6812:373
ПРОВАЛ: код вышел в сеть.
```

Любопытная тонкость: первая реплика при этом прошла — её вектор лежал
в кэше. **Кэш маскирует зависимость от сети**, и проверять надо на
вопросах, которых в нём нет.

## Два приложения

### Утилита командной строки

```bash
./ask.py --check                            # всё ли готово
./ask.py "почему сжатие бывает дороже"      # разовый вопрос
./ask.py                                     # диалог
```

```
Бэкенд: local
  ✓ индекс index-local.db: 625 кусков из 63 документов
  ✓ Ollama отвечает
  ✓ модели: qwen2.5:3b, bge-m3
  порог отказа: 0.54
```

`--check` отдельной командой не для красоты: когда что-то не работает,
человеку нужно знать, чего именно не хватает, а не «сбой соединения».
Каждая строка несёт команду для исправления.

### Окно

Главное в нём — не чат, он был в дне 26, а **счётчик обращений наружу**
слева. Он считает попытки соединения с любым адресом, кроме `127.0.0.1`,
и обновляется сам каждые три секунды. Под каждым ответом строка:

```
✓ наружу не ходили · на 127.0.0.1: 3 · 2980 ток. · 5.1с
```

Три обращения к `127.0.0.1` — это вектор вопроса, ответ и обновление
памяти задачи. Все к Ollama.

Переключатель «локально / облако» рядом: нажмите «облако», задайте тот же
вопрос — счётчик станет красным и покажет адреса.

Кнопка «Доказать офлайн» закрывает сеть совсем и прогоняет три реплики.

## Что осталось несовершенным

**Цитаты у локальной модели по-прежнему слабые.** В том же замере облако
даёт 2 подтверждённые дословно цитаты, локальная — 0. Маленькая модель
пересказывает выдержку вместо копирования, и проверка дня 24 честно
это показывает. Офлайн тут ни при чём, это свойство модели — подробности
в дне 26.

**Место на диске.** Три модели (`qwen2.5:3b`, `qwen2.5:7b`, `bge-m3`)
плюс индексы — осталось 18 ГБ из 460. Без `qwen2.5:7b` хватило бы
и десяти.

AI_ADVENT_EMBEDDINGS=local python3 ../day-21-indexing/build.py
