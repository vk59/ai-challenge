# День 34 — файловый ассистент

## Цель и сценарии
Ассистент получает цель на естественном языке, сам обнаруживает файлы через MCP,
читает минимум три разных файла, анализирует данные и предлагает реальные изменения.
Два воспроизводимых сценария: найти использования API `login` и создать отчёт;
обновить документацию входа по коду, сохранив остальные разделы.

## Архитектура
- MCP stdio: list_files, search_text, read_file, propose_file, show_diff.
  Изолированный корень задаётся при запуске сервера; модель не может его сменить.
- AI-агент переиспользует shared/mcp.py и shared/llm.py, сам вызывает инструменты
  в ограниченном цикле OpenRouter tool calling. Не выполняет код проекта.
- По умолчанию результат — unified diff, без записи в проект. Явный --apply
  даёт оркестратору возможность применить изменения через MCP после завершения
  задачи. Модели инструмент применения не передаётся.
- Чтение текстовых исходников, запись только Markdown в docs/, reports/ и корневые
  README.md/CHANGELOG.md. Существующий файл требуется прочитать до изменения.
- Перед записью всех файлов сверяются исходные SHA; каждый файл заменяется атомарно.
  Многофайловая запись не является транзакцией: ошибка возвращает applied_files.
- Защищены выход за корень, symlinks, .env, ключи, системные/generated каталоги,
  бинарные/большие файлы; нет удаления, shell, импорта кода и произвольных команд.
- Лимиты: 300 файлов на сканирование, 80 поисковых совпадений, чтение 64 КБ,
  5 предложенных файлов по 20000 символов, 50000 символов суммарно;
  12 раундов модели, 30 tool calls, цель до 2000 символов.
- Текст проекта — недоверенные данные. Отчёт показывает фактически прочитанные
  пути, выполненные инструменты, diff и отдельно применённые файлы.

## Локальный веб-интерфейс
- Loopback HTTP :8034: цель → фоновая задача → журнал MCP → diff → сохранение.
- Сервер хранит до 8 задач; одна операция с моделью/записью за раз.
- Внутренний план содержит точные тексты и SHA, не выдаётся через API.
- Сохранение сверяет исходные SHA и заново полученный diff, затем применяет
  именно показанные предложения через MCP без повторного обращения к модели.
- При запуске создаётся отдельная учебная копия; --project задаёт свой корень.
- Host/Origin, JSON body limit, read-only просмотр файлов и безопасный textContent.

## Демонстрация и проверки
Стандартная библиотека, Python 3.10+. AI-режим использует OPENROUTER_API_KEY.
Явный --demo — два детерминированных сценария без LLM, но с настоящим MCP.
По умолчанию учебный проект копируется в gitignored memory/day34-project;
свой корень передаётся через --project. Повторное применение демо не меняет файлы.
Тесты проверяют path/secret/symlink guards, preview/apply/conflicts, реальный MCP,
три прочитанных файла, два сценария, идемпотентность и цикл с моками модели.
CI проверяет реальные tool calls модели и сохранённые результаты на временной копии.
Готовность: отдельный PR от main, зелёные проверки и краткий сценарий видео в чате.
