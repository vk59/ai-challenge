# Сценарий видео — День 32. Автоматическое AI-ревью PR

**Длительность:** около 50 секунд. Покажите один тестовый PR в GitHub и готовый workflow-комментарий. Нужен заранее настроенный `OPENROUTER_API_KEY` в Actions secrets.

| Время | Кадр | Текст |
|---|---|---|
| 0:00–0:06 | Заголовок PR и несколько изменённых файлов | «Открываю pull request. Проверять его будет небольшой AI-пайплайн на GitHub Actions.» |
| 0:06–0:14 | Вкладка Actions, запуск Day 32 | «Workflow получает diff и файлы из PR, но не запускает присланный код.» |
| 0:14–0:24 | Показать шаги получения PR head и запуска `review.py` | «Контекст для поиска берётся из base-версии репозитория: документация и исходники индексируются через уже готовый RAG.» |
| 0:24–0:38 | Открыть опубликованный review-комментарий, прокрутить три раздела | «Модель возвращает потенциальные баги, архитектурные риски и рекомендации. Строки указываются только там, где их можно подтвердить по изменениям.» |
| 0:38–0:46 | Показать секреты workflow только как скрытые имена, затем README | «Ключ модели хранится в Actions secrets. Для fork PR автоматический запуск останавливается: GitHub не передаёт ему секреты.» |
| 0:46–0:50 | Вернуться к PR и папке `day-32-code-review` | «Итог — комментарий для автора PR и воспроизводимый код пайплайна.» |

## Подготовка записи

1. Добавить `OPENROUTER_API_KEY` в Actions secrets и убедиться, что workflow включён.
2. Создать тестовую ветку с небольшим намеренным изменением и открыть PR внутри репозитория.
3. Дождаться завершения `Day 32 AI code review`; проверить, что опубликован комментарий с тремя разделами.
4. Записать кадры из таблицы. Не показывать значения секретов и настройки учётной записи.

Для демонстрации без внешнего PR можно локально получить SHA base/head, запустить команду из README и показать сформированный Markdown-файл. Локальный запуск не публикует отзыв.
